01 / GET STARTED

一条指令，从这里开始。

无需先安装原版。脚本会识别现有容器，自动选择全新安装或升级。

✓ Linux 服务器✓ root 权限✓ amd64 / arm64✓ 可访问 GitHub 与镜像源

空白服务器直接安装配额版；没有 Docker 时，自动使用 Docker 官方脚本安装。

默认 8080，可按需更改

请输入 1–65535 之间的整数端口。

TERMINAL · ROOT
curl -fSL https://raw.githubusercontent.com/GYJ-gif/freegfw-quota/main/install-quota.sh -o install-quota.sh && bash install-quota.sh

在 Linux 服务器以 root 执行。已有实例升级时，请使用原面板端口。

运行前准备

准备 curl、tar、sha256sum、base64、mktemp 和 flock。全新安装还需 ss，通常由 iproute2 / iproute 提供。

首次会在服务器本地构建镜像，请预留内存和磁盘空间，等待依赖下载与编译完成。

脚本会做什么

新装会创建持久化数据卷。升级会先构建镜像，再短暂停机、备份数据并切换容器，原容器与原数据卷保留。

脚本不会修改 SSH 或防火墙。请自行在云安全组和服务器防火墙放行面板端口，以及实际使用的节点端口。

想先检查脚本，再决定运行？

先用上方命令中 && 之前的部分下载脚本，然后执行：

只检查，不部署
bash install-quota.sh --help
bash install-quota.sh --verify-bundle

--verify-bundle 只解码并校验内嵌源码，不部署服务。

02 / FIRST CONNECTION

部署之后，完成首次连接。

安装成功代表面板已启动。完成初始化和实际连接测试后，再交给其他用户使用。

  1. 01

    打开面板，设置管理员账号

    全新安装访问 http://服务器IP:8080，在“系统设置 → 基本设置”填写管理员用户名和密码并保存。首次初始化前面板没有登录保护。升级用户继续使用原地址与原账号。

  2. 02

    配置节点，创建测试用户

    点击首次部署入口，按引导配置证书；选择“我是新手”进入模板列表，选好协议后点击“部署”。然后在“本地用户管理”中添加一个独立测试用户，设置较小额度。

  3. 03

    导入订阅，检查实际连接

    将面板生成的订阅或节点链接导入兼容客户端。先确认可以连接，再进行上传和下载，检查当期配额用量是否随流量增加。

  4. 04

    验证超额断连和恢复

    让测试用户达到额度，确认现有连接中断、无法建立新连接；随后提高额度，确认能恢复连接。完成这些检查后再设置正式额度。

03 / PROTOCOLS

选择协议，配置证书和端口。

面板基于 Sing-box 与 Xray，提供协议模板。先确认客户端支持所选协议，再完成部署。

模板配置时关注什么
VLESS + TCP + Reality + Vision按模板核对 Reality 参数，客户端需支持 Reality / Vision；启用后验证计量和超额断连。
VLESS + XHTTP + Reality客户端需同时支持 XHTTP 与 Reality，导入后核对传输配置。
VLESS + TCP + XTLS准备模板要求的 TLS 证书，核对服务器名称与客户端兼容性。
Hysteria2核对证书，并在安全组与防火墙放行节点使用的 UDP 端口。
NaiveProxy核对 TLS 证书，使用支持 NaiveProxy 的客户端导入配置。
VMess + AEAD + TCP + TLS
VMess + AEAD + WS + TLS		配置 TLS 证书；使用 WebSocket 时同时核对路径等传输参数。
VMess + AEAD + TCP不含 TLS 层，不能将它视作与 TLS 模板具有相同保护；按实际用途选择。
Shadowsocks (AES-256-GCM)客户端需支持对应加密方式，保持服务器与客户端参数一致。

证书怎么配置

  1. 在首次部署引导或面板的“配置 SSL”入口打开证书设置。
  2. 按页面填写申请信息；若使用域名，先确认解析正确且服务器能够完成证书验证。
  3. 等待申请完成和服务重启。面板启用证书后，改用 HTTPS 地址访问。
  4. 使用 TLS 协议前确认已具备有效证书；面板端口与节点端口分别放行。

如需自行调整参数，可通过自定义配置入口编辑模板；不熟悉配置时，先用内置模板完成一次连接。实际可选模板以面板显示为准。

04 / CLIENTS

添加用户，把连接导入设备。

  1. 01

    为使用者创建独立用户

    打开“本地用户管理 → 添加用户”，填写方便识别的用户名。建议每位使用者单独创建用户，避免共用身份导致用量混在一起。

  2. 02

    设置限速与月度额度

    按需设置限速（Mbps）与月度配额（GB）。限速的 0 表示不限速，配额的 0 表示不限额，两者分别控制速度与总用量。

  3. 03

    打开“连接码”并导入

    在用户操作中打开“连接码”，用兼容客户端扫描二维码，或复制连接 / 订阅链接导入。手机、电脑和平板都需要使用支持所选协议的客户端。

  4. 04

    选择节点并测试

    在客户端选中导入的节点并连接，检查网页访问、上传和下载，再回到面板查看用量。节点参数改变后，按客户端方式更新订阅或重新导入。

连接码与订阅链接就是用户的连接凭据。

只分享给对应使用者，不要公开发布。删除用户前确认已不再需要其访问权限。

05 / OUTBOUND

按需启用 WARP 出站。

WARP 是服务器的可选出站隧道，不替代用户连接服务器所用的协议。

  1. 进入“系统设置 → 基本设置”。
  2. 勾选“启用 Cloudflare WARP 出站隧道”，点击“保存”。
  3. 等待配置重载，重新连接客户端并检查网络是否可用。
  4. 如果开启后无法访问，取消勾选并保存，恢复原出站后再检查服务器网络。

启用后，经过 WARP 的流量使用其出口。是否能访问某个网站或服务取决于出口与目标服务策略，不保证解除地区或账号限制。

06 / QUOTA RULES

每一份流量，都有清楚的规则。

按用户独立设置，上传与下载相加。累计历史流量和当期配额用量是不同指标。

规则具体行为
默认额度新增用户默认 150 GB / 月，可在用户行修改；0 表示不限额。
旧用户迁移首次升级时，未设置过配额的旧用户默认不限额；已有额度和当期用量保留。
计量方式上传 + 下载；1 GB = 1,000,000,000 字节。
重置时间默认每月 1 日北京时间 00:00；可选 1–31 日，没有该日期的月份按月末执行。
达到额度断开连接并拒绝新连接；下个周期自动恢复，也可提高额度后恢复。
数据保存正常退出保存用量；强杀或断电可能丢失最后约一秒用量，并发数据可能造成少量超额。
设置重置日

进入“系统设置 → 基本设置 → 月度配额重置日”，选择 1–31 日并保存。所有本地用户使用同一重置日。修改日期保留当前用量，下次按新日期重置；旧版升级默认设为 1 日，保留原周期内用量。

Vision 计量的取舍

配额版关闭可能绕过计量的原始套接字快速复制路径，这可能增加 CPU 使用。真实 Reality + Vision 场景的端到端测试仍待完成，请以本机验收结果为准。

07 / DATA & RECOVERY

升级有备份，回退有路径。

适用于已有 Docker 实例。升级前先确认旧服务正常，并保留脚本输出的备份路径。

→
02停机并备份复制 /data
→
03新数据卷启动保留原容器与数据

升级条件

现有容器需命名为 freegfw，处于运行状态，使用 host 网络，并有 /data 持久化挂载。旧面板需完成账号设置并返回登录认证要求。

恢复到升级前

备份位于 /opt/freegfw-quota/backups/。升级成功后会输出具体的 rollback.sh 路径；使用该完整路径执行，不要直接复制占位符。

示例 · 请替换为实际备份目录
bash /opt/freegfw-quota/backups/实际备份目录/rollback.sh

升级失败时脚本会尝试自动恢复旧容器。回退恢复的是升级前的数据，升级后新增用户、配置变动与流量统计不会自动合并回旧版。

后续更新请使用配额版脚本。

不要使用原版 FreeGFW 安装脚本更新这个修改版。全新安装失败时保留容器和数据卷供排查，不适用“恢复旧版”流程。

08 / TROUBLESHOOTING

遇到问题，先从这里查。

先确定是构建、面板访问还是节点连接的问题，再做对应处理。

面板打不开

确认安装输出成功、容器正在运行，访问端口与设置一致。检查云安全组及本机防火墙；服务器本地能访问，不代表公网已放行。新装默认使用 HTTP。

只读检查
docker ps -a --filter name=freegfw
docker logs --tail 100 freegfw

日志可能包含服务器信息，公开提交问题前请隐藏密码、订阅链接与私钥。

提示面板端口已占用

回到上方“一键部署”，选择未被使用的端口后重新复制命令；同时调整安全组和访问地址。不要为了释放端口直接删除不明服务。

提示 Docker 不可用或缺少工具

已安装的 Docker 不会被重装，请先确认其服务已启动。缺少其他工具时，根据报错使用对应 Linux 发行版的包管理器安装；ss 通常包含在 iproute2 / iproute 中。

镜像构建很慢或失败

首次会下载 Go 依赖和基础镜像，耗时取决于服务器网络与资源。检查输出中的下载错误、磁盘空间或内存不足。旧实例的升级在构建成功前不会停机。

重复运行提示旧面板未返回 401

如果是刚安装的空白面板，请先在页面设置管理员账号和密码。已初始化时，核对面板端口；自定义端口需通过 FREEGFW_PANEL_PORT 传入。

连接正常，但流量统计或断连不符合预期

确认运行的是配额版，并查看当期配额用量，而不是累计上传 / 下载。使用独立用户重新测试上传、下载和超额恢复。计量修复不会补算此前漏记的用量；真实 Reality + Vision 组合仍需实机验证。

09 / FAQ

你可能还想知道。

必须先安装原版 FreeGFW 吗？

不需要。上方命令可直接安装配额版；检测到已有 freegfw 容器时自动进入升级流程。

需要购买域名吗？

面板可先通过服务器 IP 和端口访问。节点是否需要域名取决于协议和证书配置：使用域名申请证书时，先把域名解析到服务器；Reality 与普通 TLS 的配置要求不同，请按所选模板填写。

能在 Windows 上直接运行安装命令吗？

不能直接在 Windows PowerShell 里运行。请通过 SSH 登录 Linux 服务器，再以 root 执行本页命令。

支持多台服务器共享一个人的配额吗？

不支持。本版只管理单机本地用户，不能将上游的节点互联能力视作本版的跨节点配额能力。
